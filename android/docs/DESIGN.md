# 星霧大陸（StarMist Walker）設計文件

Android 計步 App。核心是**準確、省電、低權限**的計步，上面疊一個「走路就是探索」的魔法奇幻世界。完全單機、離線、無帳號。

---

## 1. 需求對照

| 需求 | 做法 |
|---|---|
| 精準、背景靜默、過濾無效震動 | 硬體計步器（`TYPE_STEP_COUNTER`）+ 差值快照；無硬體時用加速度計估算（峰值偵測 + 連續步數驗證） |
| 不漏接、不耗電 | 不常駐、不持有 WakeLock；以 WorkManager 週期快照 + 開機/開啟 App/午夜補快照；硬體累計值本身不會漏 |
| 首頁直觀 + 週月年趨勢 | 首頁：步數環、距離、卡路里、達標進度；次級頁：週/月/年長條圖 |
| 權限最小化、GPS 單次主動 | 核心只要 `ACTIVITY_RECOGNITION`；GPS 軌跡為單次手動開啟（里程碑 4），不要求背景定位 |
| 激勵機制 | 星霧大陸世界（見第 6、7 節） |
| 計步可微調 | 修正係數、校準精靈、手動補登/修正、診斷頁（第 3 節） |

## 2. 技術架構

- Kotlin、Jetpack Compose、MVVM + Repository。minSdk 29（Android 10）。
- **`core` 模組**：純 Kotlin（JVM），不依賴 Android，可直接跑單元測試。所有「容易出錯的邏輯」都放這裡：
  - 差值計算（重開機偵測、首次基準）
  - 跨日分配（最大餘數法，總和守恆）
  - 修正係數 + 小數進位（不因四捨五入掉步數）
  - 加速度計步伐偵測（備援）
  - 距離/卡路里、週月年彙總、診斷判斷
- **`app` 模組**：Android 層（Room、DataStore、Sensor、WorkManager、Compose UI），只做「把平台事件餵給 core、把結果存起來和畫出來」。
- 儲存：Room（每日步數、快照狀態、之後的世界進度）、DataStore（偏好設定）。
- 世界內容（地圖、遭遇、道具表）以資料檔 + 程序化規則產生，不需要網路。

### 2.1 目錄

```
android/
 ├─ core/                 純 Kotlin，含單元測試
 │   └─ steps / metrics / stats / sensor / diagnostics
 ├─ app/                  Android 應用
 │   ├─ data/             Room、DataStore、StepRepository
 │   ├─ sensor/           StepCounterReader（一次性讀取計步器）
 │   ├─ work/             SnapshotWorker、BootReceiver、午夜排程
 │   └─ ui/               Home、Stats、Settings、Calibration、Diagnostics
 └─ docs/DESIGN.md
```

## 3. 計步核心

### 3.1 差值快照模型
`TYPE_STEP_COUNTER` 的累計值由硬體（Sensor Hub）維護，App 沒執行時也持續累加。因此**不靠持續監聽**，而是定期讀取快照、計算差值：

```
今日步數 += 目前累計值 − 上次快照值
```

- **首次安裝**：第一次讀到的值當作基準，差值為 0（開機以來的步數不屬於「今天」）。
- **重開機**：計步器歸零。偵測方式有二，任一成立即視為重開機：
  1. 目前值 < 上次快照值；
  2. 開機時間（`now − elapsedRealtime`）與上次差超過容忍值（避免「重開機後走得比之前多」被誤算成正常差值）。
  重開機時差值 = 目前累計值，且該段步數的時間範圍從「開機時間」起算而非上次快照。
- **跨日**：兩次快照之間跨過 00:00 時，依時間重疊比例分配到各天（最大餘數法，總和不變）。另外在每日 00:00 後排一次不精確的補快照，使跨日誤差通常很小。
- **行程被系統殺掉**：快照狀態每次都寫進 Room；硬體值不會丟，下次讀取即補回。

### 3.2 排程（省電）
- 不使用常駐 Foreground Service、不持有 WakeLock、不做高頻輪詢。
- `WorkManager` 週期工作（約 15–30 分鐘，由系統決定實際時機，遵守 Doze）。
- 補快照時機：開機完成、App 開啟、午夜後。
- 一次快照 = 註冊一次 listener、等待第一筆事件（逾時 3 秒）、立刻取消註冊。

### 3.3 微調功能（避免「記不到」）
| 功能 | 說明 |
|---|---|
| **修正係數** | 全域乘數，預設 1.00，範圍 0.70–1.50，可用滑桿微調；套用在每次新增的步數上，**不回頭改歷史** |
| **校準精靈** | 使用者走一段，輸入實際步數；以「實際 ÷ 感測器原始步數」算出係數；可多次測量取總和比 |
| **小數進位** | 乘數造成的小數餘數累積到下一次，長期不掉步 |
| **手動補登/修正** | 對今天或任一歷史日加減步數；保留「手動調整」欄位與原始值，可一鍵還原 |
| **步長校準** | 步長預設由身高推算（男 0.415、女 0.413、其他 0.414 × 身高）；也可輸入「已知距離 + 步數」直接算出實際步長 |
| **加速度計備援參數** | 靈敏度（過濾強度：寬鬆/標準/嚴格）、最少連續步數 |
| **診斷頁** | 感測器類型與可用性、權限狀態、最後快照時間、近期偵測到的重開機、電池最佳化狀態、一鍵立即快照；偵測到可能漏記時提示並導向補登 |

### 3.4 無效震動過濾
- 硬體計步器內建步態辨識，已能過濾大多數搖晃。
- 加速度計備援：低通濾波、動態閾值、步頻限制（約 0.5–4 Hz）、**連續 N 步才開始計入**（N 依過濾強度 4/6/8）。以合成訊號做單元測試（正常走路、高頻搖晃、零星晃動、小幅度）。
- 限制：Android 對背景加速度計有限制，備援模式在背景無法可靠運作，因此只當作「App 在前景時的估算」，並明確標示。

### 3.5 距離與卡路里
- 距離 = 步數 × 步長；卡路里 ≈ 體重(kg) × 距離(km) × 0.57（步行估算，介面標示為估算）。

## 4. 介面

- **首頁（今日）**：大圓環（步數 / 目標，預設 8,000）、三張卡片（距離、卡路里、活動時間之後加入）、世界場景（里程碑 2 起）。
- **統計**：週（7 根長條 + 目標線）、月（逐日長條）、年（12 個月總量）；區間總計、日均、最佳日、達標天數；左右切換區間。
- **設定**：個人資料、目標、修正係數、校準、補登、診斷、之後的世界與提醒設定。
- 權限被拒時：說明用途、導向系統設定；歷史資料仍可瀏覽。

## 5. GPS 戶外軌跡（里程碑 4）
- 首頁「開始戶外紀錄」按鈕，**單次主動開啟**，預設不啟用。
- 首次使用才請求 `ACCESS_FINE_LOCATION`（僅「使用 App 時」），**不要求背景定位**。
- 紀錄期間使用 Foreground Service（type=`location`）+ 持續通知（含停止按鈕）；停止即關閉，並有閒置提醒與最長時間自動結束。
- 軌跡過濾（精度、速度跳點、平滑）；結果頁顯示軌跡、距離、時間、配速；僅存本機，可刪除、可匯出 GPX。

## 6. 世界：星霧大陸

### 6.1 呈現
- **首頁：橫向視差場景**。角色與同伴在分層卷動的風景中行走，背景隨區域、日夜、季節變化。
- **世界地圖：俯視地圖**。走過的地方亮起，未探索處被星霧覆蓋；地標、聖地祭壇、遺跡標示其上。
- 用 Compose Canvas 自繪 + 少量動畫；**不用遊戲引擎、不做 3D**（省電、APK 小）。
- **旅程回放**：為省電，角色**不在背景即時動畫**。每次開啟 App，把「上次到現在的步數」做成 5–10 秒回放（可略過），途中結算遭遇與掉落。

### 6.2 世界觀
大陸下流動著**星脈**，這是維繫森林生長、潮汐節奏與生物靈性的魔法河流，世界之樹是樞紐。**星霧**降臨後星脈沉睡，各地守護靈昏睡。旅人的**腳步會留下星光**（足跡之光），能喚醒沿途的星脈。

### 6.3 區域與居民（序章 6 區）
| 區域 | 居民 |
|---|---|
| 低語森林 | 苔靈、鹿角精靈、螢光蘑菇群 |
| 月光海岸 | 潮汐鯨靈、貝殼寄居蟹商人、月光水母 |
| 珊瑚群島 | 珊瑚人魚、彩虹海馬、燈塔守護者 |
| 霧中沼澤 | 螢火蛙、沼澤女巫（神祕商人）、泥炭精靈 |
| 星砂沙丘 | 星砂狐、沙中巨龜、流沙石像 |
| 浮空遺跡 | 雲鯨、石像守衛、符文精靈 |

### 6.4 角色、同伴、能力
- **角色**：4 款外型（小狐旅人、森林精靈、貓耳少年/少女、披風旅人），僅外觀差異，可靠成就解鎖新造型。
- **同伴**：路上與遺跡撿到**神祕的蛋**，走滿步數孵化（幼龍、雲狐、小水靈…），出現在首頁場景並有小能力（例如增加某類道具的掉落）。
- **共鳴能力**（隨劇情解鎖）：喚醒、生長、潮汐、風語、星光。
- **遺跡謎題**：符文碎片轉向拼合小遊戲，約 30 秒，無失敗懲罰，可看提示。

### 6.5 探索與遭遇
- 步數是「移動力」：角色沿路線前進，**迷霧隨走過的距離揭開**。
- 每約 2,000 步一個**遭遇點**：小卡片、二選一、無失敗懲罰（例如「溪邊有隻受傷的小鹿，幫牠嗎？」）。
- 岔路：偶爾二選一（山路少 20% 步數但可能有稀有發現／河谷較慢但穩定）。
- 隱藏區域：以時段、天氣、季節、連續天數等條件出現，鼓勵在不同時間走路。
- 所有結算在**開啟 App 時一次完成**，背景不增加喚醒。

### 6.6 道具與儀式（復育/守護）
步數**不直接換能量**，而是在路途中**蒐集道具**，再到聖地祭壇舉行儀式：

| 道具 | 對應能力 | 主要來源 |
|---|---|---|
| 生命之種 | 生長（復育森林） | 森林遭遇、鹿角精靈 |
| 月光露 | 喚醒（喚醒守護靈） | 夜間行走、水邊 |
| 潮汐珠 | 潮汐（復育海岸與濕地） | 海岸遭遇、鯨靈 |
| 彩虹珊瑚芽 | 復育珊瑚 | 群島、人魚 |
| 風之羽 | 風語（吹散霧氣） | 高處、遺跡、雲鯨 |
| 符文碎片 | 星光（修復遺跡） | 遺跡謎題、石像守衛 |

流程：走到聖地祭壇 → 放入所需道具 → 5–8 秒儀式動畫 → 區域從「失衡」變「繁榮」，居民回歸、圖鑑解鎖。
**保底機制**：連續多次遭遇沒掉到關鍵道具，下次必出，避免卡關。掉落受時段、季節、同伴能力影響。

### 6.7 章節（手工設計，以更新包陸續發布）
| 章節 | 主題 | 約時長 |
|---|---|---|
| 序章：星霧 | 喚醒星脈；6 區、遺跡、第一個同伴、世界之樹 | 3–4 個月 |
| 第二章：失衡 | 星脈紊亂，重新探查舊地，儀式復育 | 2–3 個月 |
| 第三章：冰與高山 | 凍結的記憶；冰河、雪嶺、龍巢 | 2–3 個月 |
| 第四章：未來之森 | 星脈重生；世界之樹開花，終章聯動儀式 | 2–3 個月 |

### 6.8 環境變遷概念（只放進遊戲）
- **不計算減碳量、不放科普卡片或數字**，只用魔法與畫面敘事呈現「環境失衡」的概念。
- 第二章起，星脈失衡：潮汐靈沉睡、海岸退水、珊瑚褪色、森林乾枯、沼澤乾裂、冰河（第三章）的「凍結的記憶」融化。
- 舊區域被**失衡之霧**重新覆蓋，走過才揭開；以「從前 ↔ 現在」滑桿看場景前後對照。受影響的生物在圖鑑標示「受壓」，復育後變「回歸」。
- 原則：**世界不會因玩家偷懶而惡化**（變化只隨章節推進）；玩家是修復者，不被責備。

## 7. 長期動力（世界有盡頭怎麼辦）
手工章節終究有終點，所以在主線之外保留不依賴新章節的長尾：

1. **生態圖鑑深度**：同一生物有季節版、夜間版、雨天版、稀有閃光版；部分只在特定情境出現，探索度 100% ≠ 圖鑑 100%。
2. **守護繁榮度**：區域繁榮度分級，持續維護；已探索的區域保持「活著」。
3. **四季與節慶**：世界跟隨手機日期換季，每年固定回來的節慶活動（不需網路）。
4. **每日訪客與週遠征**：每天一位旅人帶一則小故事/一件小物；每週一個限時小目標，完成得專屬裝飾。
5. **年輪**：每年在世界之樹增加一圈，累積成長期的個人足跡紀錄。
6. **新章節更新包**：單機版以 App 更新發布，不需伺服器。

通用的輕量機制：彈性連續（以週計，5/7 天算達標，附保護卡）、與自己比賽的「幽靈夥伴」（上週的你/最佳日的你）、週日回顧故事、造型與稱號收集。
所有通知皆可個別關閉；沒有排行榜、沒有社交。

## 10. 風險與已知限制
- **OEM 背景限制**（小米、OPPO、vivo、三星）：差值快照對被殺進程不敏感；診斷頁提供廠牌指引。
- **無硬體計步器的裝置**：備援只在 App 前景可靠，精度較低且會標示。
- **車輛過濾**（藉活動辨識排除搭車）需要 Google Play 服務，M1 不含；硬體計步器本身已過濾大多數情況。
- **隱私**：全程離線、無帳號、無分析 SDK。
- 本文件的世界內容數值（掉落率、遭遇間隔、章節長度）為初始設定，之後依試玩調整。
