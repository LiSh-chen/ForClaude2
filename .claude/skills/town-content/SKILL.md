# 鄉鎮特色內容作業（SOP v3.4＋D18–D21）

完整規則在 `android/docs/SOP_TOWN_CONTENT.md`（決議表 D1–D21、證據分級 E1–E4、停止條件 S1–S4）與 `android/docs/REVIEW_HANDBOOK.md`（使用者意見彙整）。本檔是執行用的精簡版與檢核表；衝突時以 SOP 為準。

## 目標
每個區 2–3 條特色。每條都要：吸引人、有特色（與同類差在哪）、有記憶點（能一句話轉述）；說明是什麼、能做什麼、此地特別在哪。

## 流程（每個區）
1. **探索（研究員）**：維基整頁（用 curl 讀，見下）＋ ≥5 個獨立網域來源；統計各特色被幾個獨立網域提到（≥3＝核心特色）；十面向矩陣（農業、漁業、地景地質、生態、歷史古蹟、廟宇民俗、節慶、飲食、人物與特殊設施、交通水利）逐格記查詢字串與有／查無；寫一句話身份。提示模板：`researcher_prompt.md`。
2. **評分**：吸引人、特色、記憶點、可查證、在地性各 0–2；總分 ≥7 且記憶點 ≥1 才入選。核心特色必須五項逐項評分。使用者曾移除的項目照常重評，若核心且 ≥7 → 「建議放回」交使用者決定，同意前不寫入。
3. **撰寫**：套類型模板（必備資訊至少兩項，粗體項不可缺）。
4. **機械檢查**：`python3 android/tools/town_lint.py`（從 repo 根目錄）。E 必須為 0；每個 W 要有處置（F14＝可能重述景點卡片 D18；F15＝跨區重複 D21）。
5. **審查**：高風險區交 `town-content-reviewer` 子代理（提示模板：`reviewer_prompt.md`）；審查者不能寫檔，報告在回報訊息裡；每條要給「最終可套用句」。最多 3 輪，第 3 輪仍未過 → 依決議表降級或刪除（auto-resolved）。
6. **寫入**：`python3 android/tools/apply_town.py <changes.txt>`（先驗證再寫、自動重建字型），再 `android/tools/safe_commit.sh "訊息"`（lint 有 E 就拒絕提交）。
7. **交付**：每批列出每區最終完整句子、審查結果、被取代條目與原因、「建議放回」、無法查證清單。

## 讀取網頁
- 子代理的 WebFetch 常整批失敗，改用 Bash：`curl -sS -A "ForClaude2-research/1.0" "<網址>"`，不得在 User-Agent 放使用者信箱。
- 維基：`https://zh.wikipedia.org/w/index.php?action=raw&title=<URL 編碼的條目名>`（同名條目要用消歧名，如「溪口鄉_(台灣)」）；遇 429 先 sleep 20 秒再試，不要連打。
- 其他網站多半 403，只看搜尋摘要並如實標示；官方網頁不是必要條件，不得為了讀官網要求使用者放行網域。
- 網址只用搜尋結果給的，不憑印象猜。

## 檢核表（寫入前逐項勾）
- [ ] 每條有畫面（外觀／做法／流程），且說出此地特別在哪；不是設施清單、不是單純日常行為（走路、騎車、拍照）。
- [ ] 稱號（最、唯一、第一、全台、首…、之鄉）：兩個各自發布的來源＋句尾 ※；否則改成事實，或「曾被報導為…」＋※（只需報導存在）。※ 只能放在句尾（lint F13）。
- [ ] 傳說用「相傳／據說／一說」；單一來源細節查不到就刪（D20）。
- [ ] 會變的數字（人數、面積、造價、勝場、年抬升量）、各來源矛盾的年份不寫。
- [ ] 沒有時效詞（近年、如今、現在、目前、至今、仍…）、營運資訊、特定店名、無出處玩笑、「由…形容」這類點名機構。
- [ ] 專有名詞與人名要有白話交代（外行人看得懂）；人名譯名不一致時不寫姓名。
- [ ] 行政區：以官方地址或可靠來源確認屬該區；不在路線上的鄉鎮不放；跨區在句中交代。
- [ ] 不與景點卡片（`landmark_facts.txt`）重述同一主題（D18）；不與別區條目重複（D21）。
- [ ] 同區內不兩條講同一主題（D6）。
- [ ] 沉重或未結案的人權、轉型正義、族群爭議題材不收；原住民祭儀只寫公開報導可見部分，不寫日期與禁忌。
- [ ] 句子 14–90 字、含句號、不含半形 `:` 與 `|`；字型已重建（apply_town.py 會做）。
- [ ] 條數：2–3 條；補不到且候選池耗盡才允許 1 條；不得因刪除變成 0 條。
- [ ] 使用者曾決定的項目照使用者決定；與證據衝突只回報不擅改（S2）。
- [ ] 外部意見（其他 AI、搜尋摘要）只是線索，需自己查證。

## 風險分級（決定要不要送審查者）
需獨立審查：含稱號、歷史事件、敏感題材、行政區有疑慮、單一來源傳說、使用者曾移除項目。
可只過 lint＋檢核表：純自然／食物／設施描述且有維基全文支持的區。

## 常見失誤（本專案學到的）
- 搜尋摘要說「全台唯一」常是同一份新聞稿，不是兩個來源。
- 維基同一段文字可能混用兩個古蹟；歸屬不明就整段刪。
- 旅遊站地址可能是同一座山或園區的別處（中正公園橫跨兩區）。
- 腳本先寫檔再驗證會留下違規內容；一律先驗證再寫。
- 台帳、對照檔要由實際變更紀錄產生，不手寫。
